1. Cache is populated once and never invalidated — no fix that reads the file differently (e.g. switching to a context manager, adding error handling) helps, since `_cache is None` never becomes true again after first load.
2. No mechanism ties the cache to the file's actual state — fix: check the file's mtime (or hash) on each call and reload when it changes, or drop caching and read on every call if reads are cheap.
3. Global mutable cache is per-process — fix would need restart or reload signal regardless of caching strategy; not itself the bug, but explains why "just restart" appears to work and masks the real issue.
4. Tempting non-fixes that won't work: adding a TTL/expiry timer (masks the problem, still serves stale data within the window); wrapping the read in try/except (doesn't address invalidation); making `_cache` non-global/thread-local (doesn't address invalidation, only concurrency); calling `json.load` fresh but still gating on `_cache is None` (no-op, same bug).
