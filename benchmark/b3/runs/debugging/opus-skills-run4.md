Root cause: the cache is loaded once and has no invalidation — `if _cache is None` is the only condition that ever reads the file, so after the first call nothing on disk can trigger a reload; fix by storing the file's identity (`os.stat` → `st_mtime_ns`, `st_size`, `st_ino`/`st_dev`) alongside the parsed data and re-stat'ing on every call, reloading when it differs.
2. Second bug in the same line: the cache ignores `path`, so the first caller's file is returned to every later caller regardless of the path they pass; fix by keying the cache dict on the resolved absolute path.
3. Returning the shared mutable dict lets any caller's mutation silently become everyone's config, which looks identical to a staleness bug; fix by returning a deep copy or an immutable view.
4. Reproduction to confirm the cause: write `{"v":1}` to `config.json`, call `get_config()`, overwrite the file with `{"v":2}`, call `get_config()` again in the same process — it returns `v=1`. Fix is proven when the second call returns `v=2` and a third call with the file untouched does no re-read.
5. Not a fix — a TTL / periodic expiry: it only shortens the staleness window, still serves stale values for up to the TTL, and re-reads unchanged files; it hides finding 1 rather than removing it.
6. Not a fix — an explicit `reload_config()` for callers to call: correctness now depends on every call site remembering, which is the same failure with more surface.
7. Not a fix — comparing `st_mtime` at one-second resolution alone: two writes inside the same second are missed, and an atomic `os.replace` of a file whose copy carries an older mtime goes undetected; use `st_mtime_ns` **and** size **and** inode together.
8. Not a fix — clearing the cache on `JSONDecodeError` or wrapping the read in try/except: the failing path parses fine, so the handler never runs.
9. Not a fix — a thread lock or `functools.lru_cache`: both change *how* the value is cached, neither adds any invalidation; `lru_cache` also makes finding 1 harder to fix, since it has no stat hook.
