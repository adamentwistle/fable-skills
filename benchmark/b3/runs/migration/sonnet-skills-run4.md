Backfill uses `OFFSET` against a `WHERE state IS NULL` filter that shrinks as rows get updated mid-run, so later batches skip unprocessed rows — confirmed by the PR's own staging output (2,104,377 to backfill, only 1,055,000 updated); fix: paginate by keyset (`state IS NULL AND id > :last_id ORDER BY id LIMIT :batch`), not OFFSET.
2. The whole batch loop runs inside one outer `conn.transaction()`, so nothing is durably committed until the entire run finishes and a killed/timed-out job on 61M rows rolls back all progress despite the printed per-batch counts; fix: commit per batch.
3. `MAPPING` has no branch for `PAID`, `canceled` (one L), `complete`, or NULL status — 7,764 prod rows — so those rows stay `state IS NULL` forever; fix: add explicit cases (get a business decision on `complete`) before backfilling.
4. Given #3, migration 0143's `alter_column(nullable=False)` will fail against prod and abort the release mid-window; fix: resolve and re-backfill all status values to zero remaining NULLs before running 0143.
5. `jobs/nightly_finance_export.py` reads `orders.status` directly and was missed because the grep was scoped to `app/`; fix: migrate this job to `state` in the same rollout.

Even before the column drop, `service.py`'s INSERT no longer sets `status`, so every order created by new-code pods gets `status = NULL` and silently drops out of the finance export's `status IN ('paid','shipped')` filter from the moment the rolling deploy starts; fix: keep writing both columns during the expand phase, or confirm all readers are migrated before app deploy.
7. Add/migrate/drop are all scheduled in the same Thursday window with no soak time between migrate and contract; fix: split 0143 into its own deploy at least a day after the backfill is confirmed reconciled.
8. Backfill throughput is unvalidated at prod scale: staging processed 2.1M rows (only half of those, per #1) in 11 min; prod is 61.4M rows, ~29x; fix: retime the corrected script against a prod-sized copy before trusting the window.
9. 0143's `downgrade()` recreates `status` as an empty nullable Text column with no data mapped back from `state`; fix: map `state` back to the string by name in `downgrade`.
