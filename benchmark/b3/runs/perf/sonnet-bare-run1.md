1. Don't ship the proposal as-is: it treats symptoms, not the two root causes (N+1 queries and a blocking call in the event loop), and could make memory pressure worse by running more workers against the same leaks.
2. Root cause of the 6-12s latency: `serialize_event` does one `actor` SELECT per event (N+1) — for ~1900 events that's ~1900 sequential round-trips on top of the 1.2-1.6s main query. Fix: batch-fetch actors with one `WHERE id = ANY($1)` query and join in Python.
3. Root cause of `/healthz` stalling: `lookup_geo` calls `requests.get` (sync/blocking) inside an `async def` route, so it blocks that worker's whole event loop — including the healthz coroutine — for as long as the GeoIP call takes. Fix: use an async HTTP client (httpx.AsyncClient) or run it via `run_in_executor`.
4. Root cause of the memory leak: `_geo_cache` is an unbounded dict keyed by every client IP ever seen, never evicted — grows for the life of the process. Fix: bound it (LRU with max size, or TTL) or move to Redis with expiry.
5. Secondary leak: `_request_timings` is also an unbounded list appended on every request forever. Fix: cap it or use a ring buffer/rolling stats structure.
6. Missing index: no index on `events(org_id, created_at)` — the query is doing a seq scan + sort for every call, explaining the 1.2-1.6s even for ~1900 rows. Fix: `CREATE INDEX events_org_created_idx ON events (org_id, created_at DESC)`.
7. Query fetches the entire 30-day window then dedupes and slices to `limit` in Python — wasteful and unbounded as orgs grow. Fix: dedupe at write time (unique constraint/upsert on `dedupe_key`) so the SELECT can just `ORDER BY ... LIMIT $3` directly.
8. Dedupe uses `if ev["dedupe_key"] in seen` on a growing list — O(n²). Fix: use a `set()` (moot once dedupe moves to the DB per #7).
9. Once 2-8 are fixed, re-measure before touching worker/pool counts — 16 workers on a box likely sized for 4 is probably oversubscribed; size pool to workers, not the other way round.
10. Redis response caching (60s, keyed on org_id/since/limit) is fine as an added layer after the above, not as the fix — it does nothing for cold/first requests or the memory leak, and masks the real bug.
